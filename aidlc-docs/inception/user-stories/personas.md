# OTT 통합 피드 및 AI 추천 서비스 Personas

## Persona 설계 원칙

- 방문자, 회원, 운영자 역할을 사용자 행동과 목표에 따라 구체화한다.
- 회원은 가벼운 탐색자와 적극적 추천 사용자로 구분한다.
- 한국어·영어, 접근성, 개인정보 통제 요구를 모든 Persona의 공통 품질 조건으로 다룬다.
- AI 계층과 Recommendation Engine 등 내부 구성요소는 Persona가 아니다.

## P-01: 빠른 탐색 방문자

### Profile

- **이름**: Alex
- **역할**: 비회원 방문자
- **상황**: 여러 OTT를 구독하거나 비교 중이며 짧은 시간 안에 최신 콘텐츠를 확인하려 한다.
- **언어**: 한국어 또는 영어
- **디지털 숙련도**: 보통

### Goals

- 여러 OTT의 신작과 인기 콘텐츠를 한 화면에서 확인한다.
- 계정을 만들기 전에 작품 정보와 이용 가능한 OTT를 빠르게 비교한다.
- 제목, 인물, 장르, 연도, 국가, OTT로 콘텐츠를 탐색한다.

### Motivations

- OTT 앱을 하나씩 열어보는 시간을 줄이고 싶다.
- 지금 볼 수 있는 작품인지 확신하고 싶다.
- 데이터가 언제 갱신되었는지 확인하고 싶다.

### Pain Points

- 서비스마다 인기 기준과 표시 정보가 달라 비교가 어렵다.
- 오래되거나 지역이 다른 OTT 제공 정보는 신뢰하기 어렵다.
- 과도한 가입 유도와 복잡한 화면을 피하고 싶다.

### Behaviors

- 모바일과 데스크톱을 오가며 짧게 탐색한다.
- 피드 필터와 작품 상세, OTT 이동 링크를 주로 사용한다.
- 유용성을 확인한 뒤 회원 가입을 고려한다.

### Accessibility and Trust Needs

- 키보드 탐색, 명확한 포커스, 대체 텍스트와 충분한 색 대비가 필요하다.
- 콘텐츠 출처, 제공 지역, 마지막 갱신 시각이 보여야 한다.

### Relevant Stories

US-001, US-002, US-003, US-004, US-005, US-006, US-007

## P-02: 가벼운 탐색 회원

### Profile

- **이름**: Mina
- **역할**: 개인화 기능을 가볍게 사용하는 회원
- **상황**: 퇴근 후 또는 주말에 볼 작품을 찾지만 추천 설정에 많은 시간을 쓰고 싶지 않다.
- **언어**: 주로 한국어, 일부 영어 제목 검색
- **디지털 숙련도**: 보통

### Goals

- 구독 중인 OTT와 선호 장르를 한 번 설정하고 관련 콘텐츠를 추천받는다.
- 마음에 드는 작품을 저장하고 공개 알림을 받는다.
- 자연어 한 문장으로 상황에 맞는 추천을 받는다.

### Motivations

- 선택 피로를 줄이고 빠르게 시청을 시작하고 싶다.
- 추천 이유가 짧고 이해하기 쉬워야 한다.
- 자신의 반응이 다음 추천을 개선하길 기대한다.

### Pain Points

- 긴 설문이나 복잡한 선호 설정은 중단하기 쉽다.
- 추천 이유가 모호하거나 실제 콘텐츠와 다르면 신뢰를 잃는다.
- 원하지 않는 추적이나 알림을 부담스러워한다.

### Behaviors

- 찜, 클릭, OTT 이동 같은 가벼운 행동 신호를 남긴다.
- 추천 결과가 맞지 않으면 `조금 더 밝은 작품`처럼 한두 번 조정한다.
- 개인정보와 알림 설정을 간단히 변경하길 원한다.

### Accessibility and Trust Needs

- 개인화 데이터 사용 목적과 동의 상태가 쉽게 보여야 한다.
- AI 생성 요약과 추천 이유가 메타데이터에 근거했음을 신뢰할 수 있어야 한다.

### Relevant Stories

US-008, US-009, US-010, US-011, US-012, US-013, US-014, US-015, US-016, US-017, US-018, US-019, US-024, US-027

## P-03: 적극적 추천 사용자

### Profile

- **이름**: Jordan
- **역할**: 대화형·개인화 추천을 적극적으로 사용하는 회원
- **상황**: 기분, 동반 시청자, 시간, 장르를 세밀하게 조정하며 새로운 작품을 발견한다.
- **언어**: 한국어와 영어를 모두 사용
- **디지털 숙련도**: 높음

### Goals

- 복합적인 자연어 조건으로 정확한 추천을 받는다.
- 후속 대화로 일부 조건만 바꾸고 추천을 개선한다.
- 추천 이유, 요약, 제약 충족 여부를 확인한다.
- 자신의 평가와 행동을 통해 장기적인 추천 품질을 높인다.

### Motivations

- 단순 인기 순위보다 자신의 현재 맥락에 맞는 작품을 발견하고 싶다.
- 익숙한 장르 안에서도 반복되지 않는 다양한 추천을 원한다.
- 추천 결과를 통제하고 수정할 수 있기를 기대한다.

### Pain Points

- 하드 조건을 무시하는 추천과 존재하지 않는 작품 추천을 용납하기 어렵다.
- 후속 요청 때 이전 조건이 모두 사라지는 대화 경험을 싫어한다.
- 추천이 왜 나왔는지 설명되지 않으면 개인화를 신뢰하기 어렵다.

### Behaviors

- 평가, 저장, 다시 추천, 추천 무시를 적극적으로 사용한다.
- 추천 세션에서 여러 차례 조건을 추가·제거한다.
- 한국어와 영어 표현, 작품 원제와 번역 제목을 함께 사용한다.

### Accessibility and Trust Needs

- 추천에 적용된 조건과 변경 사항을 확인할 수 있어야 한다.
- 검증 실패 결과가 노출되지 않고 대체 추천으로 안전하게 전환되어야 한다.

### Relevant Stories

US-005, US-006, US-008, US-009, US-010, US-011, US-012, US-013, US-016, US-017, US-018, US-022, US-023, US-024, US-027

## P-04: 콘텐츠 운영자

### Profile

- **이름**: Soo
- **역할**: 작품 정보와 노출 상태를 관리하는 운영자
- **상황**: 자동 수집된 메타데이터의 오류와 격리 항목을 검토하고 사용자 노출 품질을 유지한다.
- **언어**: 한국어와 영어 메타데이터를 모두 검토
- **디지털 숙련도**: 높음

### Goals

- 승인·격리된 콘텐츠와 검증 실패 원인을 빠르게 파악한다.
- 작품 정보와 노출 여부를 안전하게 수정한다.
- AI 추천 결과가 승인된 메타데이터에 근거했는지 추적한다.
- 장애, 백업, 배포와 롤백 상태를 확인하고 복구한다.

### Motivations

- 잘못된 작품 정보나 AI 생성 문구가 사용자에게 노출되는 것을 막고 싶다.
- 변경 이력과 데이터 출처가 명확해야 문제를 재현할 수 있다.
- 단일 서버 프로토타입에서도 복원 가능한 운영 절차를 갖추고 싶다.

### Pain Points

- 공급자별 스키마와 갱신 주기가 달라 오류 원인 파악이 어렵다.
- 수동 수정이 다음 자동 수집에서 덮어써지는 상황을 피해야 한다.
- 추천과 검증 Pipeline의 어느 단계에서 실패했는지 알기 어려우면 대응이 늦어진다.

### Behaviors

- 격리 큐, 데이터 품질 상태, 감사 로그, 상태 점검과 알림을 확인한다.
- 최소한의 콘텐츠 수정과 노출 제어를 수행한다.
- 배포 실패 시 이전 이미지와 설정으로 되돌린다.

### Accessibility and Trust Needs

- 운영 기능도 키보드로 사용할 수 있고 상태를 색상만으로 구분하지 않아야 한다.
- 민감한 사용자 데이터는 최소 권한으로만 접근해야 한다.

### Relevant Stories

US-020, US-021, US-022, US-023, US-024, US-025, US-026, US-027, US-028
